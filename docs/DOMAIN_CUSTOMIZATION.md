# Domain Customization

The core Career OS should remain stable while field-specific conventions live in modules.

## What belongs in a domain module

A module may define role-family vocabulary, evidence types, artifact conventions, work samples/portfolio expectations, specialist reviewer perspective, interview formats, terminology, certifications/licenses, and common overstatement risks.

## What does **not** belong in the universal core

Do not universally require GitHub, coding skills, technical projects, publications, engineering metrics, a one-page resume, technical interviews, or any specific skills section. Likewise, do not assume marketing portfolios, finance modeling tests, or consulting cases for unrelated roles.

## How to customize

1. Start from a role family and a small sample of live JDs.
2. Identify recurring evidence categories and deliverables.
3. Identify document/work-sample conventions for the target country and field.
4. Define the third reviewer lens.
5. Define likely interview formats.
6. Define field-specific overstatement risks.
7. Add the module without changing universal evidence/human-gate rules.
8. Test it on multiple roles before promoting any new rule.

## Examples

The starter repo includes operations/business, marketing/customer-facing, and engineering/technical modules. They demonstrate adaptation; they are not exhaustive or authoritative industry standards.
