# Troubleshooting

## “The AI keeps making my experience sound bigger.”
Return to the evidence record. Separate personal contribution from team outcome, ownership from participation, and VERIFIED/SUPPORTED from HOLD/UNKNOWN. Add a `not_justified` boundary if the same inflation recurs.

## “Search keeps exploding.”
Reduce scope. One geography or a small bounded market set, a small set of role families, hard wave/role limits, and stop after discovery. Do consolidation/triage later.

## “I found a role and immediately want the resume.”
Run live-JD verification, form preflight, triage, and the human decision first. Expensive tailoring is wasted when the posting is stale, the form has a blocker, or another same-company role is stronger.

## “The resume is accurate but weak.”
Accuracy is necessary, not sufficient. Compare evidence choices, make contribution/context/result clear, and check whether finite space is being spent on the highest-value supported proof.

## “The rendered document looks wrong, so I changed the content.”
Separate semantic and render work. Geometry/wrapping can be fixed in artifact build. If the fix requires different evidence or positioning, return to compiler and re-review.

## “I generated a file, so should I mark applied?”
No. Submission requires explicit human confirmation.

## “A rejection means this role family is bad for me.”
Not from one result. Record the outcome, then treat any explanation as UNKNOWN/SUGGESTIVE unless multiple sources support it.

## “I don't know Git.”
Use the simple GitHub path in `GITHUB_GUIDE.md`; terminal use is optional for the beginner workflow.
